# Workflow Analysis

## 1. What is the purpose of using branches in GitHub?

Branches allow developers to work on changes without immediately changing the main version of a project. For this project, I used separate branches to update the About section and the team member profiles. This allowed me to make and check my changes before merging them into the main branch.

## 2. What is the purpose of a pull request?

A pull request gives developers a chance to review changes before adding them to the main branch. In this project, I created pull requests after completing changes on my feature branches. The pull requests showed exactly what had changed and allowed the changes to be reviewed before they were merged.

## 3. Why are code reviews important?

Code reviews help catch mistakes before code becomes part of the main project. They also allow developers to give feedback and learn from each other. A reviewer can check whether the code works correctly, follows the project requirements, and is easy for other developers to understand. This review process can improve the quality of the final project.

## 4. How did GitHub Actions help with this project?

GitHub Actions automated the process of checking and deploying the website. The workflow ran when changes were made to the repository. During this project, I also learned how to identify a failed deployment and correct the GitHub Pages settings. After changing the deployment source to GitHub Actions, the workflow completed successfully.

## 5. What did you learn from using this workflow?

I learned how branches, pull requests, code reviews, and GitHub Actions work together in a development project. Using separate branches made it easier to keep changes organized, while pull requests provided a clear way to review changes before merging them. I also learned that a successful code change does not always mean the deployment will succeed, so checking the GitHub Actions results is an important part of the workflow.
